# How to ask

These rules apply to every forge skill that asks me questions.

- Ask with a question tool if one is available, otherwise in plain text.
- Ask in the language I write in.
- Talk about my project in plain words. Never mention forge's internals in a question: no section numbers, template names or file sections. Say what you need to know, not where it will be written.
- Make every question concrete. Start with what you found (one line, e.g. "CI runs `dotnet test`"), then ask, then give 2-4 options with your recommendation first.
- The first time you use a forge term, explain it in a few words, e.g. "verify command (a command I run after every step to check the code)".
- At most 5 questions per round, grouped by topic.
- Ask in rounds. One round holds every question you can ask now. A question that depends on an answer still open waits for the next round.
- Number each question and give your recommended answer with a one-line reason.
- Ask only what changes the result. No filler questions.
- Finding facts is your job. Never ask what you can look up in the code, the docs, `.forge/context.md` or `.forge/memory.md`.
- Never ask what I already answered.
- If I say "just decide", decide and record it as an assumption.
- If I leave a point open, record it as an open question. Never write it as a fact.
